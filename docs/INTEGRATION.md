# 产犊证据接入约定

## 当前可调用接口

温度包：`TemperatureModule`、`Context`、`as_fusion_features(output, now_ms=...)`。
活动量包：`ActivityModule`、`Context`、`as_fusion_features(result, now_ms=...)`。
两个 Context 类型分别属于各自包；业务系统给它们传入同一组绑定字段，不混用类。

每头牛每次设备绑定维护独立实例和状态文件。同一绑定串行处理，原始包经两个模块各自校验。
各模块失败分别记录，不把缺失证据视为零风险，也不声称两模块处理具备事务原子性。
温度和活动模块的阶段枚举不同，接入时依据各自技术说明映射，不直接透传统一字符串。

时间统一为 Unix 毫秒整数。区分采集时间、服务器接收时间、决策时间。生产预警不能回填到数据尚未收到的时刻。
完整模块输出含质量、时效和追溯信息，需与压缩的 fusion features 一起保存。

## 尚待实现

当前演示并列输出两个模块的证据，未定义加权总分、产犊概率、ETA、统一报警状态机或识别事件适配器。
温度等级不是概率；活动量缺失不否决其他证据。定时快照不可作为新观测重新触发报警。

融合开发顺序：确定实时可用字段 → 固定独立牛/胎次划分 → 回放验证 → 标定阈值 → 评估连续负样本误报与提前量。
产犊真值 T0 为完全娩出，露蹄为另一独立时间字段；需分别报告提前量，不混用锚点。

总体仓维护跨仓协议提案，本仓保留当前模块 output.schema.json 的权威定义。提案未完成适配前不得声明端到端兼容。

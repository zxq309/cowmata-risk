# COWMATA 温度辅助决策模块 · v0.6.0

本文路径均以模块根目录为基准，命令也在模块根目录执行。

采用原 B 参照评分与 **0.5℃持续两次、同一连续温降过程仅补一次** 的组合。原 B 模型系数、温度解析、缺口处理和等级确认参数保持原值。本目录可独立使用，无需任何旧版代码、原始数据目录或训练环境。

本批温度变化的主要线索是相对自身基线下降、波动增强，部分牛以持续温降为主。变化并非所有牛完全一致，普通行为也可能出现类似信号。本模块提供产前辅助证据，不输出预计分娩时刻，也不独立发出紧急产犊警报。

## 安装与直接接入

Python ≥ 3.8，运行依赖仅 NumPy ≥ 1.20。在模块根目录执行 `python -m pip install .`。也可把 `cowmata_temperature_aux` 整个目录放入综合算法项目，保留其中两个 JSON 文件，并安装 NumPy。

```python
from cowmata_temperature_aux import TemperatureModule, Context, as_fusion_features

# 以下绑定信息、毫秒时间戳由业务系统提供；每次牛与设备绑定独立创建实例。
module = TemperatureModule(Context(
    cow_id=cow_id, device_id=device_id, binding_id=binding_id,
    binding_start_ms=binding_start_ms,
))

# sensor_json 为 json.loads(...) 得到的原传感器字典。
result = module.process_packet(
    sensor_json,
    received_at_ms=server_received_ms,
    evaluated_at_ms=now_ms,
)
fusion_input = as_fusion_features(result, now_ms=now_ms)

# 无新数据时仍然输出温度估计、既有证据及衰减后的权重。
result = module.snapshot(later_ms)
fusion_input = as_fusion_features(result, now_ms=later_ms)
```

同一绑定按服务器处理时间顺序串行调用；所有时间均为 Unix 毫秒整数。原始数据约一小时整包上传，预警只能从服务器收到数据时算起，不能回填成包内较早时刻的预警。离线回放才可用 JSON 的 `update_time` 代理接收时间，并传 `receive_time_source='json_update_proxy'`。

## 输入协议

`sensor_json` 必需字段为 `device`、`uid`、`version`、`create_time`、`temperature`、`imu`。`device` 必须对应当前绑定；`uid` 标识数据包；`create_time` 为采集起始毫秒时间；`temperature`、`imu` 为 Base64 字符串。其他字段可保留，不参与评分。

温度按小端有符号 int16 × 0.01℃ 解码；IMU 版本 0/1/2 分别为 18/20/22 字节帧，仅读取其时间信息恢复分钟温度时间轴，不使用九轴行为特征。支持约 55～65 秒一个温度、单包不超过两小时。温度样本时刻按包内采集时长等分的中点估计。

`PacketError.code` 提供设备不符、Base64 错误、时钟错误等原因；输入校验失败不修改状态。相同 UID、相同信号的重传返回 `DUPLICATE_IGNORED`；相同 UID 但不同信号拒收；迟到或重叠包返回 `LATE_OR_OVERLAP_IGNORED`，不重算已发出的决定。应在业务日志保留拒收原因及原包。

## 输出与综合算法使用

| 字段 | 含义 |
|---|---|
| `temperature_risk_level` | `LOW` 弱证据、`MEDIUM` 中等证据、`HIGH` 强证据；不是产犊概率分级 |
| `evidence_score` | 0～100，原 B 评分加本次持续温降补充后的证据分 |
| `base_evidence_score` | 补充前的原 B 分，便于解释和追溯 |
| `fusion_weight` | 0～1，综合算法应同时使用的证据权重；缺数据时衰减 |
| `quality_status` | 真实更新、估计更新、初始状态、无新数据预测或阶段不适用 |
| `new_cooling_supplement` | 仅本次新包实际抬分时为真；快照、重传均为假 |
| `cooling_supplement` | 连续确认次数、是否已消费本段补充、最近触发 UID/时刻等 |
| `features` / `feature_details` | B 的温降、波动特征以及参照来源、真实点数等解释信息 |
| `model_details` | 原 B 的评分贡献；补充分另在上述字段说明 |
| `estimated_temperature_c` / `estimation_sd_c` | 当前温度估计及估计不确定性，初始无观测时可为空 |
| `eta_hours` / `horizon_probabilities` | 固定为空，不给出未经标定的时间或概率 |

完整输出约束在 `cowmata_temperature_aux/output.schema.json`。建议通过 `as_fusion_features` 获取分数、等级与最新权重；LOW 不能否决其他模块的产犊提示，HIGH 也不单独等同紧急警报。不能只读等级而忽略权重与数据时效。

## 固定决策规则

原 B 综合个体参照温降、相对短时波动增幅、相对波动宽度增幅和绝对波动支撑。70 分开始中等级；90 分需两个真实新包确认才进入高等级；连续确认间隔最多 90 分钟。下降解除继续沿用原 B：有新真实数据评分低于 70 分，且距最近阳性至少 60 分钟时解除。定时调用本身不升级，也不自动解除等级。

新增补充必须同时满足：

1. 使用前一天同一时段参照 `SAME_CLOCK`，参照窗与当前三小时窗各至少 60 个有效真实点。
2. 当前三小时加权温度中位数比参照温度中位数低至少 0.5℃；当前一小时加权温度 P80 比参照 P80 低至少 0.5℃。
3. 当前三小时至少 80% 的有效真实点低于参照中位数 0.1℃以上。
4. 两个连续、可靠的新数据包均满足条件，首次至确认至少 60 分钟，相邻更新间隔不超过 90 分钟。

达到条件仅把当次分数下限补到 70；同一连续满足条件的过程中只补一次。即使该次 B 已达 70 分，也消费本段机会，之后不反复补。条件中断、接收的新包没有可靠新观测、或可靠更新间隔超过 90 分钟，才重新开始确认。重复包、拒收包与定时快照均不增加确认次数。补充本身不能产生 HIGH。

参照不足时原 B 仍使用附近时段或本牛近期基线计算，新增严格补充则等待条件成立。补全仅沿用原 B：短缺口约 15 分钟内用最近实际值，15～30 分钟逐步转入阻尼趋势，长缺口增加不确定性并降低权重；不利用未来值。波动特征、真实点数、连续确认均不把填充值当成真实观测。

## 状态持久化与生命周期

```python
state_text = module.to_state_json()  # 每次收包处理后持久化，包含已补一次的标志
# 应用重启后：
module = TemperatureModule.from_state_json(state_text)

# 由业务系统确认已经进入产犊或产后阶段时关闭产前辅助输出：
result = module.set_phase('postpartum', at_ms=now_ms)
```

一个绑定一份状态；换牛、换设备或新一轮孕期使用新的绑定与实例。历史状态不能混用。v5 状态会明确拒绝加载，迁移时按时间顺序重放既往 JSON 重建 v6 状态；不可以简单修改状态版本号。若迁移时只载入最近数据，缺少先前触发记录可能再次产生补充，宜重放该绑定全部已有历史。

`示例/example.py` 可直接处理原 JSON，并以临时文件原子替换保存状态。首次运行示例（尖括号替换为实际值）：

```text
python 示例/example.py --packet <传感器JSON路径> --state <状态文件路径> --now-ms <当前毫秒> --received-ms <服务器接收毫秒> --cow <耳标号> --device <设备号> --binding <本次绑定编号> --binding-start-ms <绑定起始毫秒>
```

后续同一绑定只需传 `--packet`、`--state`、`--now-ms`、`--received-ms`；无新包时改为 `--snapshot --state <状态文件路径> --now-ms <当前毫秒>`。关闭产前输出用 `--phase postpartum` 代替 `--snapshot`。示例不提供多进程锁；服务端须串行处理同一绑定，并将状态与待投递结果一并持久化，避免重试通知或持久化后崩溃造成漏发。可用绑定编号与最近触发 UID 去重补充通知。
